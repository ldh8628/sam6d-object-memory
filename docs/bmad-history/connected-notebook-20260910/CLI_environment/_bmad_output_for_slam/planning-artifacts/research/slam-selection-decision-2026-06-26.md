## 1. 실측 결과 (동일 데이터, RGB-D)

### 방식 B — odom vs 최적화 (보정량 = 드러난 드리프트)
| 지표 | ORB-SLAM3 RGB-D | RTAB-Map RGB-D |
|---|---|---|
| 평균 변위 | **0.067 m** | 0.185 m |
| median | 0.006 m | 0.147 m |
| p95 / max | 0.36 / 0.40 m | 0.44 / 0.65 m |
| 경로 대비 max | 1.35 % | 2.33 % |
| 경로 길이 | 29.9 m | 28.1 m |

### 방식 A — 루프 갭(최적화 전) + χ²
| 지표 | ORB-SLAM3 RGB-D | RTAB-Map RGB-D |
|---|---|---|
| **발화 루프 수** | **1** | **166** (global 120 + local 52) |
| 루프 갭 평균(전) | 0.42 m (n=1) | 0.168 m (n=114) |
| 루프 갭 max(전) | 0.42 m | 0.46 m |
| χ²(최적화 전) | — | 평균 200, median 147 |
| 갭(최적화 후) | — | **0.008 m** |
| χ²(최적화 후) | — | **평균 0.47** |

### 결정적 관찰 2가지
1. **RTAB에서 방식 A(0.168m) ≈ 방식 B(0.185m)** → 두 독립 측정이 같은 드리프트를 가리킴 = **상호 검증 성공**. 그리고 최적화 *후* 잔차 0.008m·χ² 0.47 → "최적화 후를 재면 거의 0"이라는 경고를 실증(반드시 최적화 *전*을 재야 함).
2. **ORB의 방식 B 평균이 낮은(0.067m) 것은 정확해서가 아니다.** median≈0.006m = 옵티마이저가 대부분 프레임을 안 건드림 = **루프를 1번밖에 안 닫음**. 단 한 번의 루프가 흡수한 누적 드리프트는 **0.42m**(방식 A). 즉 "작은 보정 = 루프 미검출"이라는 함정의 실증이다.

## 2. 방식 A vs B — 어느 쪽이 더 신뢰도 있는 지표인가

**판정: 방식 A(루프 갭, 최적화 전 + χ²)가 더 신뢰도 있는 "현재 위치 정확도" 지표다. 단, 발화 루프 수가 충분해야 한다. 방식 B는 값이 쉽지만 단독으로는 오도(誤導)될 수 있어 "루프 수" 가드가 필수다.**

근거(실측 기반):

| 기준 | 방식 A (루프 갭) | 방식 B (odom vs 최적화) |
|---|---|---|
| 측정 본질 | 재방문 순간의 누적 드리프트 직접 측정 | 옵티마이저가 *재분배 후* 옮긴 양 |
| 루프 수에 둔감? | **예** (이벤트 단위, 절대량) | **아니오** — 루프 적으면 값이 가짜로 낮아짐 (ORB 실증) |
| 잘못된 루프 탐지 | **가능** (χ²) | 불가 (크기만으론 정·오 구분 못함) |
| 커버리지 | 루프 지점만(희소할 수 있음: ORB n=1) | 궤적 전체(조밀) |
| 미보정 구간 희석 | 없음 | 있음(median을 0으로 끌어내림) |
| 신뢰 조건 | 루프 충분히 발화 | 루프 수와 함께 읽을 때만 |

- **루프가 조밀할 때(RTAB):** A≈B로 수렴 → 둘 다 신뢰 가능, B를 싼 대용으로 써도 됨.
- **루프가 희소할 때(ORB):** A는 1점뿐(통계적 약함)이지만 *그 1점이 0.42m라는 사실 자체*가 "이 시스템은 거의 재앵커링하지 않는다"는 강한 신호. B는 0.067m로 낮게 나와 **단독으로 보면 ORB가 더 정확하다고 오판**하게 만든다.
- **결론:** 1순위 **방식 A + χ²**, 보조 **방식 B**, 그리고 **항상 "발화 루프 수"를 동반 보고**. 이 조합이 "부드럽기만/루프를 안 닫기만 한" SLAM의 과대평가를 막는다.

## 3. 논문적 근거와 가치

| 요소 | 근거 문헌 | 가치 판정 |
|---|---|---|
| 루프=GT-free 기준점, 누적 드리프트 측정 | Engel, Usenko, Cremers, *TUM-Mono Benchmark*, arXiv:1607.02555 (2016) — 시작=끝 사실만으로 `e_t/e_r/e_s` 정의·랭킹 | **강함.** 방식 A는 이를 "끝점 1회"에서 "모든 내부 루프"로 일반화 |
| 루프 잔차 χ² 일관성 = 잘못된 루프 거부 | Latif, Cadena, Neira, *RRR*, IJRR 2013; Sünderhauf & Protzel, *Switchable Constraints*, IROS 2012 | **강함.** 방식 A의 χ²가 그대로 검증 게이트 |
| 제품 내장 동일 원리 | RTAB-Map *Robust Graph Optimization* (`RGBD/OptimizeMaxError`=3.0): 최적화 후 link 오차/σ로 루프 거부 | **강함.** 우리가 잰 χ²(post-opt 0.47)가 이 게이트 통과를 정량 확인 |
| odom vs 최적화 불일치 = 드리프트 지표 | 그래프-SLAM 드리프트 이론(Grisetti et al.), loop-closing 이득 벤치마킹 arXiv:2408.01716 | **중간.** "이름 붙은 표준 metric"이 아닌 *지표(indicator)* — 본 보고서도 그렇게 취급 |
| (대조) 단순 smoothness(jerk 등) | SLAM 평가 표준 문헌 **없음**(motion-planning/biomechanics 출신) | 정확도 지표로는 **비추천**, plausibility filter만 |

→ **방식 A는 논문적 근거가 분명하고 가치가 있다**(TUM-Mono의 GT-free 드리프트 원리 + RRR의 χ² 검증). 방식 B는 *드리프트 지표*로서 실용 가치가 있으나 표준 metric은 아니므로 "보조·가드 동반"으로 위치시키는 것이 정직하다.

## 4. 4개 지표 종합 — ORB-SLAM3 vs RTAB-Map (RGB-D, 동일 데이터)

| 지표 | ORB-SLAM3 RGB-D | RTAB-Map RGB-D | 우위 |
|---|---|---|---|
| **① 시작–끝 오차** | **0.039 m / 0.13 %** | 0.052 m / 0.18 % | ORB (근소) |
| **② 루프 자기일관성** | 갭 0.42 m, **루프 1건**, B 0.067m(median≈0) | 갭 0.168 m, **루프 166건**, B 0.185m, χ²검증 | **RTAB (압도)** |
| **③ MME (맵 선명도)** | −3.447 | **−3.974** (더 선명) | **RTAB** |
| **④ Tracking** | 1.0 (프레임 100%) | 140노드/151s 완주(키프레임 기반, 손실 없음) | 무승부* |

\* ④는 두 시스템의 정의가 달라(프레임 vs 키프레임) 절대 비교 불가 — 둘 다 손실/충돌 없이 완주.

### 해석 — ①의 함정과 ②의 진실
- **ORB의 ①(0.039m)이 근소 우위처럼 보이지만 이는 "끝점 1개" 숫자의 착시다.** ORB는 **루프를 단 1번** 닫았고, 그 1번이 흡수한 누적 드리프트가 **0.42m**였다(방식 A). 즉 그 루프가 닫히기 전까지 현재 pose는 최대 ~0.4m 어긋나 있었고, ORB는 주행 중 **사실상 재앵커링을 거의 하지 않는다.**
- **RTAB는 166번 루프를 닫아** 매 재방문마다 현재 pose를 전역 일관성으로 되돌린다. 그래서 어느 시점에서든 드리프트가 ~0.17m로 묶이고(방식 A), 맵도 더 선명(③)하다.

## 5. 최종 판단 — SAM-6D 객체 메모리용 SLAM

### 결론: **RTAB-Map (RGB-D)**

**SAM-6D 객체 메모리의 두 요구가 정확히 ②(루프 자기일관성)에 직결되기 때문이다:**

1. **객체 ID 부여 = 현재 pose를 전역 일관 좌표로 변환.** 객체를 본 순간의 pose가 틀어지면 ID가 엉뚱한 좌표에 박힌다. RTAB는 잦은 루프로 현재 pose 드리프트를 ~0.17m로 상시 억제(ORB는 루프 전 최대 0.42m 표류).
2. **동일 객체 재인식 = 재방문 시 같은 좌표로 매핑.** 이건 본질적으로 **루프 폐쇄/재방문 일관성 문제**다. RTAB는 재방문마다 루프를 닫아(166건) 같은 장소를 같은 좌표로 되돌린다 → 같은 객체가 같은 위치 → 같은 ID. **ORB는 전체 주행에서 루프 1건** → 재방문 일관성을 사실상 보장하지 못해 동일 객체가 다른 좌표로 흩어질 위험이 크다.

**근거가 되는 확실한 지표:**
- **② 루프 자기일관성(가장 결정적): RTAB 166건·χ² 검증 vs ORB 1건.** 동일 객체 재인식과 가장 정렬된 지표에서 RTAB 압도.
- **③ MME: RTAB −3.974 vs ORB −3.447** → RTAB 맵이 더 선명 = 객체 3D 배치가 더 일관.
- **① 시작–끝: ORB 근소 우위(0.039 vs 0.052m)이나 단일 끝점 착시** — ②가 그 한계를 정량적으로 폭로.
- **로버스트니스:** ORB IMU-RGBD는 종료 시 SIGSEGV(멀티맵 atlas) — IMU 변형은 현 상태로 운영 위험. RTAB는 정상 완주.

### 단서(정직한 한계)
- **데이터 1종(three_labs 3바퀴)** 결과다. `SLAM_one_lap`/`forward_backward_repeat` 등으로 재확인 권장.
- ORB는 추가 튜닝 시 루프를 더 닫을 여지가 있으나, **완화된 임계값에서도 RGB-D 1건**에 그쳤다(BoW 재방문 인식이 이 환경에선 약함).
- ④는 정의 차이로 절대 비교 불가(둘 다 완주).
- HDL-SLAM은 본 데이터에 LiDAR 자산이 없어 제외(LiDAR 확보 시 동일 ②·③ 파이프라인 적용 가능).

## 부록 A — ORB-SLAM3 IMU 정상화 + 공정 재실행 (2026-06-29 추가)

### A.1 SIGSEGV 원인 정정 및 수정
- **이전 가정(오류)**: 종료 시 멀티맵 atlas → `SaveTrajectoryTUM` 크래시.
- **실측 재진단**: 크래시는 종료가 아니라 **런 도중 frame ~2580(82%)**, 직전에 `Message queue starved` 다발. gdb로 감싸 느리게 실행 시 **starvation 0회·크래시 0회로 완주** → 과부하로 메시지가 버스트 유입될 때 ORB-SLAM3 코어 스레드가 충돌하는 **동시성 레이스(Heisenbug)** 로 확정.
- **수정**: `orb_slam.launch.py` bag play에 `--read-ahead-queue-size 5000` 추가(설정 `bag.read_ahead_queue_size`로 조정). 버스트 제거 → 레이스 창 소멸. IMU 변형 **완주(exit 0)·궤적 저장 정상**.

### A.2 공정 비교의 반전 (중요)
이전 RGB-D 수치는 read-ahead 없이 측정돼 **starvation으로 교란**돼 있었다. 동일 수정으로 양쪽을 재실행하니:

| 지표 | ORB RGB-D (정정) | ORB IMU-RGBD | 비고 |
|---|---|---|---|
| 트래킹 실패(로그) | **0** (이전 24) | **0** | 24회는 IMU 부재가 아니라 **starvation 아티팩트**였음 |
| 재배치(Relocalized) | **0** (이전 3) | **0** | 동상 |
| 추적 프레임 | 4324/4545 (100% fed) | 4110/4324 (95%) | RGB-D가 오히려 소폭 많음 |
| 시작–끝 드리프트 | **0.038 m / 0.13%** | 0.139 m / 0.48% | RGB-D 우위 |
| 궤적 gap / jump | 39 / 28 | 37 / 18 | 사실상 동급 |
| MME | -3.443 | -3.422 | 동급 |
| 루프 자기일관성 ②(방식 A) | **루프 1개** | **루프 1개** | IMU도 루프 수 안 늘림 |
| 방식 B 변위 | 0.059 m (회전 1.9°) | 측정불가(중력정렬로 회전 96° 오염) | RGB-D만 유효 |

### A.3 정정된 결론
- **IMU는 이 데이터에서 ORB의 정확도·강건성을 의미있게 개선하지 못함.** starvation 버그를 고치면 RGB-D도 트래킹 실패 0으로 깨끗이 추적하며, 드리프트는 오히려 더 낮다(0.13% vs 0.48%). 부드러운 실내·충분한 특징·depth 스케일 환경이라 비전 단독으로 잘 구속되기 때문. (이전의 "IMU가 손실 24→0 제거" 잠정 결론은 교란에 의한 오판으로 폐기.)
- **RTAB-Map 선정은 불변, 오히려 강화**: ORB는 **IMU를 켜도 루프 1개**에 그쳐, RTAB의 166개와의 격차(②)는 모드와 무관한 아키텍처 차이임이 재확인됨.
- ORB를 쓴다면 **IMU보다 RGB-D 단독이 더 단순·정확**(IMU 초기화 리셋·중력정렬 부작용 없음).

### A.4 방법론 정정 + 실시간(1.0x) 검증
- **read-ahead ≠ rate**: `--read-ahead-queue-size`는 디스크→메모리 선읽기 개수일 뿐 발행 타이밍(타임스탬프×rate)을 바꾸지 않는다. "느리게 해서 프레임을 더 먹인" 것이 아니라, 디스크 I/O 병목으로 **늦게·뭉텅이로** 나가던 메시지를 **예정 타이밍대로** 복원한 것.
- **실시간(1.0x) 재검증** (both, read-ahead 적용):

| 지표 @1.0x | RGB-D | IMU |
|---|---|---|
| 완주/크래시 | 정상 / 0 | 정상 / 0 |
| queue starved | 0 | 0 |
| Track fail / Reloc | 0 / 0 | 0 / 0 |
| 추적 프레임 | 4313 (~94%) | 4119 |
| TrackRGBD 평균 | **12.4 ms (80 fps)** | 13.7 ms (73 fps) |
| 시작–끝 드리프트 | **0.038 m / 0.13%** | 0.050 m / 0.17% |
| gap / jump | 39 / 26 | 37 / 19 |
| MME | -3.434 | -3.401 |
| 루프 | 1 | 1 |

- **해석**: 카메라 30fps(프레임 간 33ms)인데 TrackRGBD가 ~13ms → **실시간에서도 여유롭게 따라가며 프레임 드롭 거의 없음(~6%)**. 즉 이전 starvation은 compute가 아니라 **디스크 I/O** 문제였고, 1.0x에서도 조건이 "쉽다". 따라서 IMU가 구제할 어려운 구간(빠른 모션·블러·시야 가림)이 발생하지 않아 **실시간에서도 IMU≈RGB-D(드리프트는 RGB-D가 근소 우위)**. IMU 가치를 보려면 빠른/공격적 모션 데이터가 필요.
